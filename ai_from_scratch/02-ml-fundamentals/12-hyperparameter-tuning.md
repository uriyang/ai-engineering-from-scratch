# 하이퍼파라미터 튜닝

> 하이퍼파라미터는 학습이 시작되기 전에 정하는 손잡이다. 어떤 손잡이를 얼마나 돌리느냐가 평범한 모델과 좋은 모델을 가른다.

## 핵심 아이디어

모델은 훈련 중에 파라미터를 배운다. 하지만 학습률, 트리 깊이, 정규화 강도, 배치 크기처럼 학습 방법 자체를 정하는 값은 사람이 먼저 정해야 한다. 이것이 하이퍼파라미터다.

```text
파라미터:
훈련 데이터로부터 학습되는 값
예: 가중치, 편향, 트리 split threshold

하이퍼파라미터:
훈련 전에 정하는 값
예: learning_rate, max_depth, lambda, batch_size
```

하이퍼파라미터 튜닝은 가능한 설정을 여러 번 평가해 좋은 조합을 찾는 과정이다. 하지만 모든 조합을 다 해보는 것은 금방 불가능해진다.

예를 들어 6개의 하이퍼파라미터가 있고 각각 5개 후보가 있다면:

```text
총 조합 수 = 5^6 = 15,625

한 번 학습에 10초라면:
15,625 * 10초 = 156,250초 ≈ 43.4시간
```

그래서 튜닝의 핵심은 “많이 돌리기”가 아니라 “제한된 예산 안에서 어디를 볼지 잘 정하기”다.

## 대표 하이퍼파라미터

| 하이퍼파라미터 | 조절하는 것 | 일반적인 범위 |
|---|---|---|
| 학습률 | 한 번 업데이트할 때 움직이는 크기 | `0.001` ~ `1.0` |
| 추정기 수 / 에폭 수 | 얼마나 오래 학습할지 | `10` ~ `10000` |
| 최대 깊이 | 트리 또는 모델 복잡도 | `1` ~ `30` |
| 정규화 강도 | 과적합 방지 강도 | `0.0001` ~ `100` |
| 배치 크기 | 그래디언트 추정의 노이즈 | `16` ~ `512` |
| 드롭아웃 비율 | 무작위로 끄는 뉴런 비율 | `0.0` ~ `0.5` |

중요도는 모델마다 다르지만, 많은 경우 learning rate와 정규화 강도가 가장 먼저 봐야 할 값이다.

## Grid Search

Grid search는 미리 정한 값들의 모든 조합을 평가한다. 이해하기 쉽고 재현하기 쉽지만, 차원이 늘어나면 비용이 지수적으로 증가한다.

```text
learning_rate: [0.01, 0.1, 1.0]
max_depth:     [3, 5, 7]

평가 조합:
(0.01, 3)  (0.01, 5)  (0.01, 7)
(0.1,  3)  (0.1,  5)  (0.1,  7)
(1.0,  3)  (1.0,  5)  (1.0,  7)

총 평가 수 = 3 * 3 = 9
```

Grid search의 문제는 모든 축을 똑같이 중요하게 취급한다는 점이다. 실제로는 6개 하이퍼파라미터 중 1~2개만 성능 대부분을 좌우하는 경우가 많다.

중요한 하이퍼파라미터가 learning rate 하나뿐인데, grid가 각 축에 3개 값만 둔다면 9번 평가해도 learning rate는 3개 값만 본다. 나머지 평가는 중요하지 않은 축의 조합을 바꾸는 데 쓰인다.

| 장점 | 단점 |
|---|---|
| 단순하고 설명하기 쉬움 | 차원이 늘면 조합 폭발 |
| 완전 탐색이 가능하면 안정적 | 중요하지 않은 축에도 예산 낭비 |
| 작은 탐색 공간에 적합 | 연속값을 촘촘히 보기 어려움 |

Grid search는 하이퍼파라미터가 1~2개이고 후보 값이 작을 때 좋다. 예를 들어 Ridge/Lasso의 `alpha` 하나를 로그 스케일로 찾는 경우에는 충분히 강하다.

## Random Search

Random search는 각 하이퍼파라미터를 분포에서 무작위로 샘플링한다. 같은 9번 평가라도 grid search보다 중요한 축을 더 촘촘히 볼 수 있다.

```text
Grid search 9회:
learning_rate의 고유 값 3개
max_depth의 고유 값 3개

Random search 9회:
learning_rate의 고유 값 최대 9개
max_depth의 고유 값 최대 9개
```

Bergstra와 Bengio의 2012년 논문이 보여준 핵심은 다음과 같다.

- 대부분의 문제에서 유효 차원은 낮다.
- 즉, 많은 하이퍼파라미터 중 일부만 성능에 크게 중요하다.
- Grid search는 덜 중요한 차원에 평가를 낭비한다.
- Random search는 같은 예산으로 중요한 차원을 더 다양한 값에서 탐색한다.

Random search는 특히 다음 상황에서 좋다.

| 상황 | 이유 |
|---|---|
| 하이퍼파라미터가 많음 | 중요하지 않은 축에 덜 묶임 |
| 어떤 값이 중요한지 모름 | 넓게 탐색 가능 |
| 연속형 값이 많음 | grid보다 다양한 값을 샘플링 |
| 빠른 기준선이 필요함 | 구현이 단순하고 병렬화 쉬움 |

## 탐색 분포가 중요하다

Random search는 “무작위”라고 해서 아무 분포나 쓰면 안 된다. 하이퍼파라미터가 모델에 영향을 주는 스케일에 맞춰 샘플링해야 한다.

학습률과 정규화 강도는 보통 로그 스케일로 탐색한다.

```text
나쁜 예: linear uniform
0.001, 0.112, 0.223, ..., 1.0

좋은 예: log-uniform
0.001, 0.003, 0.01, 0.03, 0.1, 0.3, 1.0
```

`0.001`과 `0.01`의 차이는 `0.1`과 `1.0`의 차이만큼 중요할 수 있다. 선형 분포로 뽑으면 큰 값 근처에 예산이 과하게 몰린다.

| 값 종류 | 추천 분포 |
|---|---|
| 학습률 | 로그 균등 분포 |
| 정규화 강도 | 로그 균등 분포 |
| 최대 깊이 | 정수 균등 분포 또는 작은 후보 목록 |
| 배치 크기 | 후보 목록: `16`, `32`, `64`, `128` |
| 드롭아웃 | 균등 분포: `0.0` ~ `0.5` |
| 활성화 함수 | 범주형 분포 |

## 베이지안 최적화

Random search는 이전 평가 결과를 기억하지 않는다. learning rate가 너무 크면 계속 망한다는 사실을 알아도, 다음 샘플링에 자동으로 반영하지 않는다.

베이지안 최적화는 지금까지 평가한 결과를 바탕으로 “다음에는 어디를 평가하면 좋을지”를 고른다.

```text
1. 탐색 공간을 정한다.
2. 초기 몇 개 지점을 무작위로 평가한다.
3. 평가 결과로 surrogate model을 학습한다.
4. acquisition function으로 다음 후보를 고른다.
5. 실제 모델을 그 후보로 학습해 점수를 얻는다.
6. 결과를 추가하고 3~5를 반복한다.
7. 예산이 끝나면 가장 좋은 설정을 반환한다.
```

핵심 구성요소는 두 가지다.

| 구성요소 | 의미 |
|---|---|
| 대리 모델 | 비싼 실제 목적함수를 싸게 근사하는 모델 |
| 획득 함수 | 다음에 평가할 후보를 고르는 점수 함수 |

대리 모델은 보통 가우시안 프로세스, 트리 구조 파젠 추정기, 랜덤 포레스트 같은 모델을 쓴다. 중요한 점은 예측값뿐 아니라 불확실성도 추정한다는 것이다.

## 탐색과 활용

베이지안 최적화는 두 욕구 사이에서 균형을 잡는다.

```text
활용:
이미 좋아 보이는 곳 근처를 더 자세히 본다.

탐색:
아직 모르는 곳, 불확실성이 큰 곳을 본다.
```

획득 함수는 이 균형을 숫자로 만든다.

| 함수 | 의미 |
|---|---|
| 기대 개선량 (EI) | 현재 최고점보다 얼마나 좋아질 것으로 기대되는가 |
| 신뢰 상한 (UCB) | 예측 평균 + 불확실성 보너스 |
| 개선 확률 (PI) | 현재 최고점보다 좋아질 확률 |

기대 개선량은 다음 후보가 현재 최고점보다 얼마나 개선될지의 기대값을 본다.

```text
EI(x) = E[max(f(x) - f_best, 0)]
```

예측 평균이 높으면 EI가 커진다. 불확실성이 커도 “대박 가능성”이 있으므로 EI가 커질 수 있다. 그래서 EI는 exploitation과 exploration을 함께 반영한다.

## 세 방법 비교

| 방법 | 이전 결과 사용 | 장점 | 단점 | 추천 상황 |
|---|---|---|---|---|
| Grid search | 아니오 | 단순, 완전 탐색 | 차원 증가에 취약 | 작은 탐색 공간 |
| Random search | 아니오 | 넓고 효율적인 탐색 | 좋은 영역을 학습하지 않음 | 기본 선택지 |
| 베이지안 최적화 | 예 | 평가 횟수 절약 | 구현과 설정이 복잡 | 학습 비용이 큰 모델 |

대략적인 감각은 다음과 같다.

```text
작은 문제:
Grid search도 충분하다.

대부분의 일반 문제:
Random search가 강력한 기본값이다.

한 번 학습이 비싼 문제:
베이지안 최적화로 평가 횟수를 아낀다.
```

## Early Stopping

모든 trial을 끝까지 학습할 필요는 없다. 어떤 설정은 초반부터 명확히 나쁘다. 이런 trial을 빨리 중단하고 예산을 더 가능성 있는 설정에 쓰는 것이 early stopping 또는 pruning이다.

| 전략 | 의미 |
|---|---|
| 인내 횟수 기반 | 검증 성능이 N번 연속 개선되지 않으면 중단 |
| 중앙값 가지치기 | 같은 step의 완료 trial 중앙값보다 나쁘면 중단 |
| 하이퍼밴드 | 많은 설정에 작은 예산을 주고, 좋은 설정만 더 큰 예산으로 승격 |

부스팅이나 신경망에서는 추정기 수 또는 에폭 수를 작게 튜닝하기보다, 충분히 크게 잡고 early stopping으로 멈추는 편이 좋다.

```text
나쁜 접근:
추정기 수 후보를 [50, 100, 200]으로만 둔다.

좋은 접근:
추정기 수를 크게 두고 validation 성능이 멈추면 중단한다.
```

## Hyperband

Hyperband는 여러 설정을 토너먼트처럼 평가한다. 처음에는 많은 후보에게 작은 학습 예산을 주고, 성능이 좋은 일부만 다음 라운드로 올린다.

```text
라운드 1:
81개 설정을 1 에폭씩 학습
상위 27개 유지

라운드 2:
27개 설정을 3 에폭씩 학습
상위 9개 유지

라운드 3:
9개 설정을 9 에폭씩 학습
상위 3개 유지

라운드 4:
3개 설정을 27 에폭씩 학습
최종 선택
```

모든 81개 설정을 27 에폭씩 끝까지 학습하는 것보다 훨씬 싸다. 초반 성능이 어느 정도 최종 성능을 예측할 수 있는 문제에서 특히 효과적이다.

## Learning Rate Scheduler

학습률은 가장 중요한 하이퍼파라미터 중 하나다. 고정된 값 하나를 쓰기보다, 학습 중에 조절하는 scheduler를 쓰면 안정성과 성능이 좋아질 수 있다.

| 스케줄러 | 식 또는 동작 | 사용 상황 |
|---|---|---|
| 계단식 감소 | N 에폭마다 일정 비율로 감소 | 전통적인 CNN 학습 |
| 코사인 어닐링 | `lr * 0.5 * (1 + cos(pi * t / T))` | 현대적인 기본 선택지 |
| 워밍업 후 감소 | 처음엔 선형 증가, 이후 감소 | Transformer |
| 원 사이클 | 한 번 올렸다가 내림 | 빠른 수렴 |
| 정체 시 감소 | 지표가 멈추면 감소 | 안전한 기본값 |

Warmup은 특히 큰 모델에서 중요하다. 초반에 학습률을 너무 크게 쓰면 모델이 불안정해질 수 있으므로, 낮은 학습률에서 시작해 목표 학습률까지 천천히 올린다.

## 어떤 하이퍼파라미터가 중요한가

모든 값을 같은 열정으로 튜닝할 필요는 없다. 성능에 큰 영향을 주는 값부터 봐야 한다.

| 중요도 | 하이퍼파라미터 | 설명 |
|---|---|---|
| 높음 | 학습률 | 너무 크면 불안정, 너무 작으면 느림 |
| 높음 | 정규화 강도 | 과적합과 과소적합을 직접 조절 |
| 높음 | 추정기 수 / 에폭 수 | early stopping으로 다루는 편이 좋음 |
| 중간 | 최대 깊이 / 층 수 | 표현력과 분산을 조절 |
| 중간 | 리프 최소 샘플 수 / 가중치 감쇠 | 일반화에 영향 |
| 중간 | 부분 샘플링 비율 | 부스팅의 분산과 다양성 조절 |
| 낮음 | 최대 특징 수 | 랜덤 포레스트에서는 기본값도 강함 |
| 낮음 | 활성화 함수 세부 선택 | 합리적 후보 안에서는 영향이 작을 수 있음 |
| 낮음 | 배치 크기 | 너무 극단적이지 않으면 보통 2차적 |

좋은 전략은 상위 2개 정도에 예산 대부분을 쓰고, 나머지는 넓게 확인하는 것이다.

## 실전 튜닝 전략

```text
1. 라이브러리 기본값으로 기준선을 만든다.
2. 넓은 범위에서 거친 무작위 탐색을 20~50회 한다.
3. 결과를 보고 중요한 하이퍼파라미터와 좋은 범위를 찾는다.
4. 좁힌 범위에서 세밀한 무작위 탐색 또는 베이지안 최적화를 50~100회 한다.
5. 가장 좋은 설정으로 훈련 데이터를 다시 학습한다.
6. 마지막 테스트 세트는 한 번만 본다.
```

중요한 원칙:

- 처음부터 좁게 찾지 않는다.
- best 값이 탐색 범위의 경계에 있으면 범위를 넓힌다.
- 학습률과 정규화 강도는 로그 스케일로 찾는다.
- 부스팅과 신경망은 early stopping을 사용한다.
- validation set에 너무 많이 맞추지 않는다.

## Cross-Validation과 Nested CV

하나의 validation split에서 튜닝하면, 우연히 그 split에 잘 맞는 하이퍼파라미터를 고를 수 있다. 이를 validation set overfitting이라고 볼 수 있다.

K-fold cross-validation은 여러 split에서 평균 성능을 보기 때문에 더 안정적이다.

```text
K-fold CV:
데이터를 K개 fold로 나눈다.
각 fold를 한 번씩 검증 fold로 사용한다.
K개의 점수를 평균낸다.
```

최종 성능을 엄밀하게 보고해야 한다면 nested cross-validation을 쓴다.

```text
Outer loop:
최종 평가용 test fold를 분리한다.

Inner loop:
남은 데이터 안에서 하이퍼파라미터를 튜닝한다.

Evaluation:
inner loop에서 고른 설정을 outer test fold에 평가한다.
```

Nested CV는 비싸다.

```text
outer 5-fold * inner 5-fold * grid 27개
= 675번 모델 학습
```

하지만 논문, 중요한 의사결정, 모델 비교 보고처럼 신뢰할 수 있는 일반화 성능이 필요할 때는 이 비용을 낼 가치가 있다.

## 모델별 추천 탐색

| 모델 | 먼저 볼 값 | 추천 방법 | 예산 |
|---|---|---|---|
| Random Forest | 추정기 수, `max_depth`, `min_samples_leaf` | Random search | 낮음 |
| Gradient Boosting | `learning_rate`, 추정기 수, `max_depth` | Bayesian + early stopping | 중간 |
| Neural Network | `learning_rate`, `weight_decay`, `batch_size` | Bayesian 또는 random | 높음 |
| SVM RBF | `C`, `gamma` | 로그 스케일 grid | 낮음 |
| Ridge/Lasso | `alpha` | 1D 로그 탐색 | 매우 낮음 |
| XGBoost | `learning_rate`, `max_depth`, `subsample`, `colsample` | Bayesian + early stopping | 중간 |

튜닝 예산이 적다면 random search를 기본값으로 잡는다. 최소한 하이퍼파라미터 개수의 2배 이상은 trial을 돌리는 것이 좋고, 가능하면 50회 정도가 꽤 강한 기준선이 된다.

## 데이터 누수와 검증 세트 과적합

튜닝에서 가장 위험한 실수는 검증 정보가 훈련 과정에 새는 것이다.

| 실수 | 문제 | 해결 |
|---|---|---|
| 전체 데이터로 scaler를 fit한 뒤 CV | 검증 fold의 통계가 훈련에 들어감 | preprocessing을 Pipeline 안에 넣기 |
| validation set으로 수천 번 튜닝 | validation set에 간접적으로 과적합 | 별도 test set 또는 nested CV |
| best가 범위 경계에 있음 | 최적점이 범위 밖일 수 있음 | 탐색 범위 확장 |
| 독립적인 값처럼 튜닝 | learning rate와 estimator 수처럼 상호작용 놓침 | 관련 값은 함께 탐색 |
| 최종 test를 여러 번 확인 | test set도 튜닝 대상이 됨 | 마지막에 한 번만 평가 |

전처리는 반드시 교차검증 fold 안에서 fit되어야 한다. 예를 들어 표준화, 결측치 대체, 특징 선택, PCA는 모두 validation fold를 보기 전에 훈련 fold만으로 fit해야 한다.

## Optuna 같은 도구를 쓸 때

실무에서는 직접 Bayesian optimizer를 구현하기보다 Optuna 같은 라이브러리를 많이 쓴다. 중요한 패턴은 다음과 같다.

```python
def objective(trial):
    learning_rate = trial.suggest_float("learning_rate", 1e-4, 1e-1, log=True)
    max_depth = trial.suggest_int("max_depth", 2, 10)
    subsample = trial.suggest_float("subsample", 0.5, 1.0)

    model = Model(
        learning_rate=learning_rate,
        max_depth=max_depth,
        subsample=subsample,
    )
    model.fit(X_train, y_train)
    return validation_score(model, X_val, y_val)
```

Optuna에서 자주 쓰는 기능:

- `suggest_float(..., log=True)`: 로그 스케일 탐색
- `suggest_int`: 정수 하이퍼파라미터
- `suggest_categorical`: 범주형 선택
- pruner: 나쁜 trial 조기 중단
- `study.trials_dataframe()`: trial 결과 분석

도구보다 중요한 것은 검증 설계다. 좋은 optimizer도 데이터 누수를 고쳐주지는 않는다.

## 튜닝 결과를 읽는 법

튜닝은 best score 하나만 보는 작업이 아니다. 다음 질문을 같이 봐야 한다.

```text
1. best 값이 탐색 범위 경계에 있는가?
2. 같은 점수대의 설정이 여러 개인가?
3. 특정 하이퍼파라미터가 성능과 강하게 상관되는가?
4. trial 간 점수 분산이 큰가?
5. 검증 성능과 테스트 성능 차이가 큰가?
```

best 값이 경계에 있으면 탐색 공간이 잘못됐을 수 있다. 비슷한 성능의 설정이 많다면, 더 단순하고 안정적인 설정을 고르는 것이 좋다. 한 점만 우연히 높다면 재검증이 필요하다.
